# Plotting review — FitSession and CPFitSession — 2026-09-10

Scope: one-dimensional projections, signal/background curves, yield normalization, charge separation, efficiency/veto, and the helpers in plotting.py. The findings describe the initial review; applied fixes are recorded at the end.

## 1. High: precomputed backgrounds are silently omitted from the total

`workflow.py::_projection_components` and `cp_workflow.py::_projection_components_pair`.

Sessions accept BackgroundCategory/CPBackgroundCategory in the NLL, but plotting executes `continue` for categories that are not BackgroundSpec/CPBackgroundSpec. The curve labeled "total fit" ends up without those backgrounds, even though the signal remains scaled by the signal fraction.

Reproduction with signal fraction 0.6:

- FitSession with 20 events and a BackgroundCategory: signal only, sum 12; expected total 20.
- CPFitSession with 20 events per charge and a CPBackgroundCategory: signal only, joint sum 24; expected total 40.

These numbers are weight sums before histogramming, so they do not result from truncation by the plot range.

Recommendation: require an evaluable shape for the projection of these categories, or allow supplying a corresponding projection sample/template. If there is not enough information, fail explicitly rather than drawing an incomplete "total fit". Background values only at the data events do not, in general, define their expected projection on a new sample.

## 2. High on the mismatched-size path: the CP split sums instead of averaging per sample

`cp_workflow.py::_joint_scaled_weights`.

The helper sums the weights of both samples directly. The integration convention is mean(weights*density), so each charge needs to be divided by its own point count before combining.

Reproduction: symmetric model, 40 data events in total; the minus projection sample obtained by repeating the plus sample's points and weights exactly four times. The estimated integral of each charge remains identical, but the curve weights end up summing to **8 plus and 32 minus**, instead of **20 and 20**.

The public `plot_projection` currently generates the same number of points per charge, so this particular factor cancels on that path. The defect affects the helper and the `_projection_components` wrapper, which uses the models' normalization samples: adaptive grids or external MC can have different sizes.

Recommendation: normalize the integral estimates by each sample's N. To preserve exactly the charge probabilities reported by the NLL, also use the fit's integrals/probabilities to set each charge's yield, and use the projection sample only to distribute those yields among bins. Today the public plot re-estimates the asymmetry with the projection MC, so it can differ statistically from the NLL even with equal sizes.

## 3. Medium: the CP projection fails when one charge has empty data

`cp_workflow.py::plot_projection`, hist_range construction.

Without an explicit `range`, each panel computes min/max from its own data. If one charge has zero events, the reduction fails with `ValueError: zero-size array to reduction operation minimum which has no identity`.

Reproduction: 20 plus events, zero minus, NR model, projection_size=100.

Recommendation: build common bin edges from the physical domain or the combined data, explicitly handling the fully empty case. Common bin edges also allow comparing B+ and B- on the same binning: currently the default ranges are computed separately.

## 4. Medium: zero-yield components still require a positive projection integral

`workflow.py::_scaled_projection_weights` and `cp_workflow.py::_joint_scaled_weights`.

Integral validation happens before scale is considered. `_scaled_projection_weights(sample, zeros, 0)` raises ValueError instead of returning zero weights. Components are prepared even when the requested yield is zero.

This can block the projection of mixtures at the limit, or of a missing component whose support is not represented in the drawing MC. The test confirms the helper's behavior; it does not prove failure of an entire zero-yield mixture, since components with a positive integral still pass.

Recommendation: skip missing components before evaluating their density, returning zero contribution. For positive yields, keep an explicit diagnostic for a non-positive or non-finite integral.

## Controls and observations

- FitSession multiplies the proposal weight by the accepted density and scales each component to its yield. In the shape-based configuration, backgrounds receive the veto according to apply_veto, and efficiency enters the signal. I found no evidence of double-applied efficiency on this path.
- `show_components=False` only hides the individual curves; the total is still accumulated.
- Curves are scaled over the full domain before the histogram is cropped. Therefore a restricted drawing range can legitimately show fewer events than the total yield; the visual selection must not be automatically renormalized.
- `plot_binned_data` uses sqrt(N) for unweighted data and sqrt(sum(w²)) when weights are supplied. Sessions show event counts, consistent with their unweighted NLLs; the PhaseSpaceSample weights used in integration must not be automatically treated as statistical weights of the data.
- FitSession reuses projection samples and amplitudes. CPFitSession generates two full samples on every call and reevaluates the intensities; this deserves optimization for large models, but is not, by itself, a statistical error.
- Total curves do not show the projection MC's uncertainty. Bin fluctuations are not necessarily a fit failure.

## Validation performed

CPU/float64, matplotlib Agg backend, two cores: **20 passed in 8.39 s**, in `tests/test_workflow.py`, `tests/test_cp_workflow.py`, and `tests/test_plotting.py`.

Additional reproductions were run in a separate process. The empty-charge case called the public plotting API; the count checks examined the weights feeding the histograms. No visual inspection of exported figures was performed in this review.


## Applied fixes

- Active precomputed categories without a projection shape now cause an explicit error requesting a BackgroundSpec/CPBackgroundSpec, instead of being omitted from the total. A shape cannot be reconstructed from values at the fit events alone.
- The joint-weights helper divides each sample by its own size. CP projections use the fit's signal integrals and category probabilities to fix each charge's yield; each drawing MC only distributes the corresponding yield among the bins.
- CP panels share bin edges computed from the combined data. One empty charge is accepted; two empty datasets require an explicit range.
- A zero-yield signal is not evaluated, zero-yield backgrounds are skipped, and helpers return zero weights for zero scale. Negative/non-finite yields and invalid integrals of active components still raise an error.

Validation: 24 tests passed in 9.95 s, plus a CP-background control comparing the projected yields against the NLL's probabilities. This includes plots via Agg, common bin edges, an empty charge, mismatched MC sizes, a missing signal, and explicit rejection of backgrounds without a shape. No change to the NLL or the fit result.
